# Проверки

## Быстрые проверки

```bash
npm ci
npm run check
```

5 модульных тестов: полнота курсов и лицензий, схемы с 11 игроками, экранирование HTML, критерии практики, подсчёт слов и навигация. `vite build` проверяет реальную production-сборку.

## Браузер

```bash
npx playwright install chromium
npm run test:e2e
```

Если Chromium уже установлен в `/usr/bin/chromium`, конфигурация использует его; альтернативный путь: `CWM_CHROMIUM_PATH=/path/to/chromium`. В CI ставятся браузер и системные зависимости через `playwright install --with-deps chromium`.

10 сценариев (5 × desktop/mobile): открытый кабинет, фильтрация курсов, отсутствие горизонтального переполнения, обязательные задания урока, тактическая доска, учебный наставник без API, защита от HTML-инъекции, пробный тест и ограничения личных страниц. Для стабильности открытые тесты отключают внешнее Supabase-подключение переменными тестового сервера, не меняя пользовательский `.env.local`.

Скриншоты: `test-results/desktop-dashboard.png` и `mobile-dashboard.png`. Trace записывается при ошибке.

## Настоящий PostgreSQL / RLS

```bash
docker run --name cwm-test-db \
  -e POSTGRES_PASSWORD=cwm-local-only \
  -p 127.0.0.1:55432:5432 -d postgres:17-alpine
npm run test:db
# После проверки:
docker rm -f cwm-test-db
```

Используется только одноразовая локальная БД на `127.0.0.1:55432`. Скрипт удаляет её схемы перед проверкой и отказывается работать с удалённым адресом. Никогда не направляйте его на проект Supabase. `tests/auth-shim.sql` моделирует `auth.users`, `auth.uid()` и роли для интеграции с чистым PostgreSQL; это не миграция продакшена и не проверка доставки писем Auth.

В тестах выполняются обе реальные миграции. Затем проверяются изоляция двух пользователей, запрет записи ролей/баллов/лицензий, недоступность ключей, черновики, запрет пропуска уроков, полноценное завершение курса, снимок экзамена, серверный подсчёт теории, очередь ручной проверки, запрет самопроверки, транзакционная выдача одного сертификата, CRUD администратора и блокировка.

## Edge Functions

Нужен Deno 2. Проверка выполняется без внешнего ИИ и без секретов проекта:

```bash
DENO_DIR=/tmp/cwm-deno npm --cache /tmp/cwm-npm-cache exec --yes --package=deno@2.9.6 -- deno test --allow-env --node-modules-dir=manual tests/edge.test.ts
```

6 тестов реальных обработчиков с подменой HTTP-ответов Supabase/ИИ: отклонение неверного JWT до RPC, серверный запрет admin-действия, точный CORS origin, отключённый провайдер, исчерпанная квота и ошибка 429 провайдера без раскрытия ключа и без использования URL из браузера. Это проверка логики функций, не подключение к удалённому Supabase.

## Приёмка опубликованного сайта

После подключения реального Supabase и Pages выполните список в конце SUPABASE.md. Локальные тесты базы и интерфейса не доказывают, что в конкретном удалённом проекте применены миграции, настроены SMTP/redirect URLs, опубликованы функции или доставляются письма. Эти действия проверяются отдельно на подключённом проекте.
